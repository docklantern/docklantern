# DockLantern v0.1.0-beta.4.1

## Image-first Management Experience

This candidate completes the beta.4 monitoring-only dashboard after the existing beta.4 tag was created. It adds the operator-validated readability and running-image provenance changes while preserving opt-in Compose-first registry monitoring.

- **Overview:** Watched-image counts, remote-change and conservative deployed-image assessments, errors and Images to Review.
- **Images / Image Details:** Canonical image/platform grouping, search/filter/sort, digest evidence, image-scoped history and associated services.
- **Services / Service Details:** Project-grouped Compose inventory, runtime context, monitoring interval provenance, and authenticated enable/disable, override/reset and pause/resume controls.
- **Activity:** Searchable/filterable image-specific events, exact digest evidence, cursor pagination and webhook delivery details.
- **Settings:** Global monitoring, notifications, retention and Advanced / Legacy Configuration.

## Improvements in this candidate

- More readable typography and contrast across tables, sidebars, forms, timestamps, badges and digests with local-only font fallbacks.
- An embedded **running binary version** shown in the sidebar and logged at startup.
- Explicit distinction between the **Docker-observed running container image** and its inventory timestamp, versus the **persisted registry watch reference**. A legacy watch for an older version does not prove the container itself is old.
- Guidance for comparing Docker `Config.Image`, immutable image ID, binary version and effective Compose image. Pulling an image and restarting an existing container does not replace its original image.
- Policy-interval-aware registry observation freshness and regression coverage for independent notification and retention settings.
- Automated tests for image scope and platform evidence, service controls, auth/security behavior, backwards compatibility and history semantics.

## Monitoring-only guarantees

- No automated image pulls, Compose deployments, target-container recreation/restarts, or Docker API write access.
- Existing authentication, origin/CSRF protections, SQLite policy and event history, and restricted read-only Docker proxy are retained.
- A remote digest change is not proof of a newer software version; insufficient deployed-image evidence is reported as Unknown.

## Known limitations

- Single host and a single process-wide registry credential host/account; SQLite history groups image + platform rather than credential scope. Independent per-service scopes for the same image reference and cross-rotation credential-scope-aware history are not supported (issue #45).
- Changing Docker Compose monitoring labels requires the operator to recreate the **target** service using their own normal workflow.
- Multi-host orchestration, semantic tag policy and any deployment automation remain future work.
