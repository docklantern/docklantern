# DockLantern v0.1.0-beta.4 — Draft release notes

**Status: DRAFT / not published.** Do not tag or publish the release, update GHCR or Docker Hub, or change the VPS without explicit operator approval.

## Image-First Management Experience

Beta.4 reorganizes the existing monitoring-only interface into five first-class workspaces:

- **Overview** — image-centric counts and prioritized review queue, meaningful events and small worker summary.
- **Images** — canonical image/platform grouping, search/filter/sort, actual registry digest evidence and associated services on a dedicated details page.
- **Services** — project-grouped Compose services, conservative deployment status, runtime context and service-scoped monitoring forms.
- **Activity** — date-grouped retained registry events, search, event/delivery filters, exact image-scoped links, cursor pagination and optional delivery details.
- **Settings** — global defaults, notifications and retention; legacy manual controls under Advanced.

### Quality improvements during release validation

- Monitoring staleness considers the fastest active watcher and its configured interval (minimum two-hour freshness window), avoiding false stale alerts for slow polling intervals.
- Notification preferences no longer unintentionally rewrite event-retention settings from an old browser tab.
- New acceptance/compatibility tests cover group evidence, image scope, security boundaries, URL/HTML escaping, monitoring controls and independent settings.
- PR #58 improves small-text legibility and secondary-label contrast using local system font fallbacks; no remote font services are introduced.
- The sidebar and startup log now identify the **running binary build version**. Services and Service Details distinguish the **Docker-observed container image** and its inventory time from the independently persisted **registry watch reference**. A legacy policy can point to an older image without proving the container itself is old.
- Running-image troubleshooting documents why pulling and restarting an existing Docker container does not replace its underlying image. No Docker privilege or schema changes were introduced.

## Preserved guarantees

- No Docker image pulls, container recreation/restarts, automatic updates, or Compose deployments.
- No expansion of Docker socket privileges.
- Existing authenticated service controls and CSRF/origin checks preserved.
- Existing SQLite policy/event data, conservative deployment evidence, API behavior and HTTPS deployment model preserved.
- A changed remote digest **is not** evidence of a newer software release.

## Supported assumptions / limitations

- Single host and one process-wide registry credential host/account. In-memory registry cache scopes results by effective credentials, but **SQLite observations and GUI grouping currently use image+platform only**. Multiple independent auth scopes for the same image are not supported, and historical baselines may need resetting after credential-scope changes.
- Monitoring is periodic; changes to Docker labels require recreating the *target application service* through the operator's existing process.
- Event retention pruning is manual and only affects expired delivered events.
- Multi-host orchestration and any form of deployment automation are out of scope.
