# DockLantern v0.1.0-beta.3

**Monitoring-only beta release.** DockLantern provides read-only Docker Compose image monitoring and remote OCI digest observations; it never pulls, restarts, recreates, or redeploys monitored containers.

## Highlights

- **Zero-configuration, opt-in Docker label monitoring:** Add `com.docklantern.monitor: "true"` to a Compose service. After the service is recreated by its operator, DockLantern discovers the label on its next inventory scan and creates a watch without source mounts, `-roots`, registration forms or restarting DockLantern.
- **Live monitoring preferences:** Configure the global interval (initially five minutes), optional `com.docklantern.interval: "10m"` service labels, and persistent GUI interval overrides. Priority is GUI override → label → default. GUI opt-in for unlabeled discovered services, pause/resume and reset are supported.
- **Consistent, service-first GUI:** Shared sidebar on Overview, Events and Settings, service-level monitoring health/status, direct links to settings/history and clear interval provenance.
- **Accurate event semantics:** Remote OCI digest changes are image/platform-scoped observations, not proof of a newer application version or a DockLantern-initiated update. Webhook delivery state is displayed separately from registry-check state.
- **More efficient registry polling:** Bounded, credential-scoped OCI observation reuse and `Retry-After` cooldowns; service schedules, failure backoff and history remain distinct.
- **Safe legacy upgrade:** Transactional SQLite schema migrations preserve beta.2 registrations, existing manual policies, schedules, digest baselines and event history.

## Images

The release workflow publishes multi-platform `linux/amd64` and `linux/arm64` Docker images:

- `ghcr.io/docklantern/docklantern:v0.1.0-beta.3`
- `davidslusser/docklantern:v0.1.0-beta.3`

Verify published manifest digests before deployment; prefer pinning the immutable manifest digest in production.

## Minimal Compose configuration

```yaml
services:
  web:
    image: example/web:latest
    labels:
      com.docklantern.monitor: "true"
      # Optional; default is configurable in the GUI:
      com.docklantern.interval: "10m"
```

The `monitor=true` label is deliberately opt-in. `monitor=false` explicitly blocks checks even when GUI or legacy enrollment exists. The monitoring proxy remains GET-only and private.

## Upgrade caution

**A beta.2 to beta.3 upgrade migrates the SQLite schema to version 3.** Make a consistent SQLite backup first, verify `PRAGMA integrity_check`, save the backup off-host, and retain the old image tag/digest. Reverting the binary alone is **not** a safe rollback; restore the corresponding pre-upgrade database snapshot and journal state.

The release only publishes images. It **does not** update the user's running VPS, Traefik or separately managed workloads. Consult [release-validation checklist](https://github.com/docklantern/docklantern/blob/main/docs/deployment/beta3-release-checklist.md) and the [deployment documentation](https://github.com/docklantern/docklantern-deploy).

## Known limitations

- The application remains monitoring-only; no automatic deployment or update actions.
- Docker discovery is periodic; changing a label requires recreating the *target service* using its normal Compose workflow.
- Registry digest movement does not establish software semantic-version direction.
- Registry observation caching is local to one running DockLantern scheduler.
- Multi-host scheduling, Docker event streaming and team-wide RBAC are deferred.
