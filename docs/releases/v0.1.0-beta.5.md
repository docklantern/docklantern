# DockLantern v0.1.0-beta.5

## Actionable image monitoring

This beta enhances DockLantern's monitoring-only web interface so operators can choose a registry tag to watch, request a registry check, and see monitoring diagnostics **without changing their Docker Compose configuration or running containers**.

### New capabilities

- **Watched-tag override:** On an eligible Service Details page, choose a valid, explicitly tagged OCI reference in the **same registry and repository** as the Docker-observed image. The registry watch is independent of the deployed Compose image. Reset to the latest verified Docker-observed tag at any time.
- **Safe recovery:** A detected external Compose change to a different image repository blocks an obsolete watch. A validated reset can recover the watch from the new Docker-observed identity without restarting or enrolling an otherwise disabled service.
- **Check Now:** Service Details and Image Details can request a remote registry observation for an enrolled and eligible service or image/platform group. Requests are persisted in SQLite and processed on the existing background monitoring tick; they are **not** synchronous registry requests or image pulls.
- **Bounded scheduling:** Paused, unenrolled, explicitly disabled and conflicting services remain ineligible. Persistent retry/backoff and registry rate limits cannot be overridden; shared image/platform watches have a one-minute manual-request/recent-check cooldown and deduplicated observation behavior.
- **Clear diagnostics:** Service Details identifies the running Docker image, current registry watch and its source, effective polling interval, last monitoring attempt, last successful registry observation, manual-request time, failure count and next scheduled check. Image Details explains the eligible watcher count and requested image/platform scope. Messages distinguish a scheduled or deferred request from a successful registry check.

### Reliability and security

- Adds regression tests across watched-tag overrides, Check Now scheduling, explicit label opt-outs, shared images, distinct platforms, stale in-flight results, registry backoff, restart persistence, form authorization and cross-origin/CSRF protections.
- The security-audit workflow now runs for Go source-code changes, including monitoring and HTTP-handler PRs.
- Continues the **monitoring-only** model: no target image pulls, Docker API write access, Compose execution, service recreation/restart, automatic updates or rollback execution.

### SQLite schema upgrade and rollback

This release advances the embedded SQLite schema from **v3 to v5** via transactional migrations:

- **v4** stores an optional per-service watched-image reference, preserving existing monitoring policies, settings, pauses and history.
- **v5** persists a manual Check Now request timestamp so throttling and scheduled work survive DockLantern restarts.

Take and verify a **consistent application-backed SQLite backup before upgrading**. Older beta.4.1 binaries cannot safely open schema v5. Rollback requires restoring the corresponding **pre-upgrade SQLite database snapshot**, not merely switching Docker image tags. Follow the [beta.5 acceptance and recovery checklist](../deployment/beta5-test-vps-acceptance.md).

### Known limitations

- Monitoring does not determine whether a changed registry digest represents a newer semantic software release. The deployed-image assessment is conservative and can remain **Unknown** when evidence is insufficient.
- Explicit watch overrides are limited to tag changes in the Docker-observed image's registry/repository and verified platform. Cross-repository watch edits and semantic tag selection policies are not supported.
- Legacy/manual monitoring policies retain their existing configuration path; the new watched-tag form does not rewrite them.
- Registry credentials remain **process-scoped**; persisted image history is keyed by OCI reference and platform, not by credential identity. Multiple independent credential scopes for one image and credential-rotation-aware history require future design work ([#62](https://github.com/docklantern/docklantern/issues/62)).
- Running beta.5 on a real host and validating performance, IPv6 reachability, backup recovery and browser functionality require operator-run acceptance. Automated CI evidence does **not** establish that deployment testing has occurred.
